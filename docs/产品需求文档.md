# 知了森林 · 产品需求文档（PRD）

**版本** v1.0 ｜ **日期** 2026-09-13 ｜ **赛事** 知乎黑客松 2026 · 知识炼金场赛道

---

## 1. 背景与机会

### 1.1 一个普遍但被忽视的失败

知乎用户普遍存在「**收藏即知晓**」的幻觉：点赞收藏了几百篇深度长文、专业干货，在评论区高谈阔论，在收藏夹里囤积着"未来的自己"。但当深夜点开那个庞大的收藏夹时，心里泛起的是心虚与虚无——**知识只是被"看见"了，从未被理解、吸收**。

这不是用户懒。知乎上已有大量同类讨论印证这是结构性问题：

- [知乎收藏夹 34 个夹、上千条吃灰：我把整理搬出了知乎，才发现方向一直搞反了](https://zhuanlan.zhihu.com/p/2078995245765748551)
- [为什么你的知识库会变成僵尸库？——收藏夹吃灰，不是你的错](https://zhuanlan.zhihu.com/p/2071979198063948628)
- [如何将各平台收藏的有用知识串联起来进行系统化学习？](https://www.zhihu.com/question/1929498111656567100/answer/2065514774578861895)

### 1.2 现有工具为什么没解决

| 类别 | 代表产品 | 解决了什么 | 没解决什么 |
|------|---------|-----------|-----------|
| 稍后读 / 收藏管理 | [Raindrop.io / Readwise](https://fabric.so/comparison/raindrop-vs-readwise)、[Cubox](https://toolchase.com/alternatives/cubox/)、[Matter](https://toolchase.com/alternatives/matter-app/) | 存得下、找得到 | **不回看**；不告诉你"你是什么样的人" |
| 年度报告式可视化 | [Spotify Wrapped](https://lbbonline.com/news/Spotify-From-First-Party-Data-to-First-Class-Storytelling)、[网易云年度报告](https://www.thepaper.cn/newsDetail_forward_33271598) | 情绪价值极高，是社交货币 | **一年一次**，是"回望"不是"日常" |
| 个人知识图谱 | [Heptabase / Obsidian / NotebookLM](https://zhuanlan.zhihu.com/p/2078497056310797296)、[loci](https://github.com/lmanhes/loci/) | 有结构、有连接 | 需要用户**主动输入与整理**，门槛高 |
| 游戏化习惯养成 | [蚂蚁森林](https://www.nature.com/articles/s41599-026-07058-6) | 强驱动力 | **打卡负担重**，[流失用户研究](https://www.tandfonline.com/doi/pdf/10.1080/10447318.2025.2536626) 显示繁重感是主要流失原因 |

**关键洞察**：收藏类工具解决"存"，报告类产品解决"看"，图谱类工具要求"做"。
**没有人解决"不知不觉地长出来"。*

### 1.3 机会点

> Pocket 已经关停（见 [9 款稍后读工具实测](https://dev.to/gomilesf/i-tested-9-read-it-later-apps-in-2026-after-pocket-died-3fg9)），说明"纯存储"品类的商业模型不成立。**价值必须落在"理解"而非"保存"上。**

**知了森林的切入点**：不做又一个收藏夹，而是把**已有的浏览行为**转化为**可视化的自我认知**——用户什么都不用做，森林自己会长。

## 2. 目标用户

### 2.1 核心用户

**知乎重度用户**（主力人群）

| 维度 | 描述 |
|------|------|
| 特征 | 使用知乎 1 年以上，收藏夹 ≥ 100 条 |
| 行为 | 遇到好内容先收藏，"以后再读"；深夜会突然打开收藏夹感到焦虑 |
| 痛点 | ① 收藏从没回看 ② 说不清自己真正关心什么 ③ 算法推荐不准，因为平台不知道他的深度兴趣 |
| 诉求 | 想"看见"自己的兴趣结构；想被理解；不想增加负担 |

### 2.2 三个演示画像（对应数据集）

| 画像 | 特征 | 产品要回答的问题 |
|------|------|-----------------|
| **深潜型探索者** | 兴趣集中，一个领域持续加深 | "你在人工智能上走了很远" |
| **突然转向的漫游者** | 人文底色，中段冒出新兴趣 | "你最近变了" |
| **广而不深的收藏家** | 兴趣极度发散，没有主干 | "你收藏很多，但没有一棵树长成" |

## 3. 产品定位

### 3.1 一句话定位

> **一个会自己生长的兴趣森林，让你看见自己真正知道什么。**

### 3.2 价值主张

| 对象 | 价值 |
|------|------|
| **用户** | 零操作获得自我认知；不焦虑的成长感；可分享的社交货币 |
| **平台** | 修剪/浇水信号是**高置信度的兴趣反馈**，可显著改善推荐质量 |
| **知识生态** | 把"收藏"这一沉睡资产激活为可探索的知识路径 |

### 3.3 命名与叙事

**知了** = 蝉，也是"知道了"。
> 你以为你知道了，但你真的知道了吗？

知了精灵是产品的拟人化载体：治愈手绘风的小精灵在森林里飞，帮你修剪、浇水、清理枯叶。它比抽象的 AI 图标更讨喜，也让"AI 帮你整理知识"这件事有了情绪温度。

## 4. 核心设计原则

| 原则 | 含义 | 反面案例 |
|------|------|---------|
| **零负担生长** | 森林自动长，不要求打卡 | 蚂蚁森林的每日能量收取 |
| **AI 代劳** | 提取、归类、摘要、写日记全由 AI 完成 | 要求用户手动打标签的图谱工具 |
| **视觉优先** | 一切用图形表达，不用表格和列表 | 传统知识管理工具的树形目录 |
| **轻交互校准** | 只保留"修剪/浇水"两个动作，且都是可选的 | 复杂的设置面板 |
| **有温度** | 用"枯萎/浇水/随风而去"代替"删除/保留" | 冷冰冰的回收站 |

## 5. 用户旅程

```
首次进入
  ↓
授权读取浏览历史（或使用演示数据）
  ↓
AI 聚类 → 森林首次生成（种子 → 幼苗 → 树）
  ↓                                    ←—— 核心惊喜时刻
每日打开
  ↓
森林因昨天的行为自动生长 + 知了精灵飞过来打招呼
  ↓
① 看光合作用报告卡（昨天读了什么）
② 打开农夫日记 —— 顶部是「你的灵魂画像」，下面是这周的变化日记
③ 可选：修剪不感兴趣的枝 / 给枯萎的叶浇水
  ↓
画像随新内容缓慢演化；更新时卡片上出现「已更新」标记
```

**关键设计**：画像与日记**同页不同层**——画像是锚（稳定、低频、视觉最强），日记是流（每日刷新）。每个画像特质的"依据"直接链到下方对应的日记条目。

**关键情绪曲线**：第一次打开 → 惊喜（"这是我的？"）→ 每天打开 → 安心（"又长了一点"）→ 一段时间后 → 感动（"原来我是这样一个人"）

## 6. 功能需求

### 6.1 P0（MVP，必须做）

| ID | 功能 | 验收标准 |
|----|------|---------|
| F01 | 数据接入 | 能读取带时间戳的内容列表（收藏/点赞/搜索） |
| F02 | 主题聚类 | AI 把内容聚成"树（大主题）+ 叶（小主题）"，**树 ID 跨天稳定** |
| F03 | 森林渲染 | 展示多棵树，位置/大小由数据决定，视觉为治愈手绘风 |
| F04 | 生长动画 | 新内容到达时，对应树有新叶长出的动画 |
| F05 | 知了精灵 | 有飞行动画与状态机（待机/飞行/修剪/浇水/清理） |
| F06 | 修剪/浇水 | 点叶片可修剪或浇水，产生 `FeedbackSignal` |
| F07 | 光合作用报告 | 每日卡片：昨天的高质量输入 + AI 摘要，按 `voteUpCount` 排序 |
| F08 | **灵魂画像 + 农夫日记** | **两个页面**：`/profile` 是灵魂画像锚点（灵魂类型 + 3-5 个特质，每个特质带一句话依据 + 注意力分布），`/diary` 是变化日记流（新增/猛增/衰退）。两页互为证据 |
| F09 | 按天回放 | 可演示"森林从无到有"的生长过程 |
| F10 | 演示兜底 | AI 失败时读预生成森林，Demo 不翻车 |

> 说明：原「F09 兴趣画像」已并入 F08。画像的定位是**锚**而不是日记流里的一条——流水账会淹没"你是谁"这个低频高价值信息。实现时进一步把锚独立成了 `/profile`，日记留在 `/diary`，两页互为证据。

### 6.2 P1（有余力则做）

| ID | 功能 | 理由 |
|----|------|------|
| F11 | 分享卡片生成 | 传播力；Wrapped 类产品的核心机制（画像卡 + 报告卡） |
| F12 | 昼夜/季节氛围 | 设计感加分 |

### 6.3 P2（明确不做，答辩时说明为后续规划）

| 功能 | 砍掉理由 |
|------|---------|
| 展示/隐藏我的树（原 F13） | 不影响任何评分维度。森林页的定位是「森林当主角 + 周边三个悬浮入口」，再加一个树列表控件是往回走。**改为后续规划**（更值的做法是点树名收起，零 UI 成本） |
| 拜访他人森林 / 隐私叶子模型 / 圈子 | 需多用户体系与权限模型，48h 做不完；赛道是"知识炼金场"不是社交 |
| 推送通知（7:00/22:00） | 演示环节体现不出，且需移动端 |
| 3D 化 | 性价比极低，2D 手绘风更贴治愈感 |

## 7. 数据与合规

### 7.1 数据来源

- **演示数据**：真实知乎内容（通过知乎官方 CLI 检索）+ 编排的时间线
- **真实接入**：知乎开放平台 Access Secret；黑客松 OAuth

### 7.2 合规要求（必须遵守）

| 要求 | 说明 |
|------|------|
| 保留署名 | 展示内容时一并展示作者与原文链接 |
| 不冒认创作 | 不得声称内容由本应用或当前用户创作 |
| 只读最小范围 | 只读取完成任务所需的数据 |
| 如实说明 | 答辩中说明"内容真实、时间线为演示编排" |

## 8. 成功指标

| 维度 | 指标 | 目标 |
|------|------|------|
| 体验 | 首次生成森林的"惊喜度" | 用户主动截图分享 |
| 留存 | 次日回访 | 因为"想看看长成什么样了" |
| AI 价值 | 用户是否认可画像准确 | "说得挺准的" |
| 算法价值 | 修剪信号量 | 每次会话 ≥ 1 条 |

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 知乎数据接口不可用 | 数据管道断裂 | 已有 **191 条真实内容数据集（3 用户 × 30 天）** + 预生成森林兜底 |
| AI 调用延迟/失败 | 演示卡住 | `expected-forest/` 预生成缓存 |
| 树 ID 不稳定 | 森林每天洗牌 | 契约强制"增量归类复用 ID" |
| 森林布局难看 | 演示效果差 | 用圆盘撒点，稳定且自然 |
| 现场网络不可控 | 演示翻车 | 所有 AI 结果预生成，演示读本地 |
