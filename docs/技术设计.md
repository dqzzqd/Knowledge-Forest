## 1. 架构总览

```
┌─────────────────────────────────────────────────────────┐
│  浏览器 (Next.js App Router / React)                     │
│  ┌────────────┐ ┌────────────┐ ┌──────────────────┐     │
│  │ 森林场景    │ │ 光合作用报告 │ │ 农夫日记          │     │
│  │ SVG+Motion │ │ 卡片        │ │ （画像锚 + 日记流）│     │
│  └────────────┘ └────────────┘ └──────────────────┘     │
└───────────────────────┬─────────────────────────────────┘
                        │ fetch  (统一外壳 {success,data,error})
┌───────────────────────▼─────────────────────────────────┐
│  服务端 (Next.js Route Handlers)                         │
│  ┌──────────────────────────────────────────────────┐   │
│  │ AI 编排层  ai/                                    │   │
│  │  classify · summarize · detectChanges            │   │
│  │  report · profile · sprite                       │   │
│  └──────────────────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────────────┐   │
│  │ 森林引擎  forest/                                 │   │
│  │  ingest → assign → grow → layout → snapshot      │   │
│  └──────────────────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────────────┐   │
│  │ 数据层  data/   JSON / SQLite                    │   │
│  └──────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
                        │
        ┌───────────────┴────────────────┐
        ▼                                ▼
  知乎开放平台 CLI                 大模型（离线批量生成）
  (数据源 / 真实接入)              (聚类·摘要·叙事)
```

**核心分层原则**：AI 只负责"语义判断"，不负责"状态管理"。森林的树 ID、生长、布局全部由确定性代码控制——**AI 的输出可失败，森林不能崩**。

## 2. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 框架 | **Next.js (App Router) + TypeScript** | 前后端一体，48h 最快 |
| 样式 | **Tailwind CSS** | 快速实现设计稿 |
| 可视化 | **SVG + CSS 补间** | 手绘风天然是 2D；3D 性价比极低。动画量小，没必要引动画库 |
| 状态 | React `useState` / `useReducer` | 不做全局状态库，过度设计 |
| AI | **大模型离线生成产物**（OpenAI 兼容接口，本项目用 `deepseek-chat`） | 聚类/摘要/叙事质量高；产物入库、运行时只读，断网也能跑 |
| 数据 | **JSON 文件**（演示）/ SQLite（可选） | 48h 不值得引入 Postgres |
| 精灵 | Sprite 图 + CSS/JS 补间 | 比 Lottie 更可控，比 3D 轻 |
| 部署 | 知乎 AiWorks（Next.js `standalone` → CloudBase 云函数） | 官方托管 |

**明确不用**：Redux、Three.js、Postgres、GraphQL、Microservices。

## 4. AI 层设计

### 4.1 六个调用（契约 §5）

| # | 函数 | 输入 → 输出 | 触发时机 |
|---|------|------------|---------|
| 1 | `classify` | 新内容 + 已有树 → assignments | 每日同步 |
| 2 | `summarize` | 内容批次 → 摘要 | 聚类后 |
| 3 | `detectChanges` | 时间窗前后叶子活跃度 → events | 每日 |
| 4 | `report` | 当日高质量内容 → 报告 | 每日 |
| 5 | `profile` | 全局统计 → 画像 | 按需 |
| 6 | `sprite` | 动作 + 上下文 → 台词 | 交互时 |

### 4.2 关键约束

**① 输出必须是纯 JSON**
用工具调用（tool use）或 JSON mode 强制结构化，禁止自由文本。

**② 批量而非逐条**
一次调用处理一批内容（如 10-20 条），48h 内降低成本与延迟。

**③ 增量优先，避免全量重算**

```ts
// 错误做法：每天全量重新聚类 → 森林洗牌
const trees = await classify(allContents);

// 正确做法：只归类新增，复用已有树 ID
const { assignments } = await classify({
  existingTrees: currentForest.trees,   // ← 关键
  newContents: todayOnly,
});
```

**④ 缓存优先**

```ts
// 演示时先读缓存，命中直接返回
const cached = await readCache(key);
if (cached) return cached;
```

### 4.3 降级策略

| 阶段 | 失败表现 | 降级 |
|------|---------|------|
| classify | 超时/报错 | 新内容进 `category: null`，森林不变 |
| detectChanges | 失败 | 农夫日记空数组，不阻塞其他模块 |
| report | 失败 | 显示"今天没什么特别的" |
| 全部失败 | — | 读 `expected-forest/` 兜底 |

**原则**：任何 AI 失败都不应让用户看到白屏或报错。

## 5. 前端设计

### 5.1 森林渲染

```
ForestCanvas
├── <svg viewBox="0 0 1 1">          ← 归一化坐标
│   ├── <TreeGroup> × N              ← 每棵树
│   │   ├── <Trunk />                 ← 按 stage 切换形态
│   │   └── <LeafGroup>               ← 按 leafIds 渲染叶片
│   │       └── <Leaf> × M            ← hover / click / 状态色
│   └── <Cicada />                    ← 精灵（独立层，z-index 最高）
└── <Backdrop />                      ← 昼夜氛围
```

**为什么用归一化坐标**：后端给 `{x: 0-1, y: 0-1}`，前端映射到任意视口，响应式零成本。

### 5.2 生长动画

| 事件 | 动画 |
|------|------|
| 新叶 | `scale: 0 → 1`，弹性缓动，延迟按索引错开 |
| 新树 | 从地面 `translateY` 升起 + 轻微摇摆 |
| 枯萎 | 颜色过渡到枯黄 + 轻微下垂 |
| 浇水 | 水珠粒子 + 颜色回鲜 |

用 CSS 过渡 + 定时器逐帧重算处理增删，避免手动管理 DOM。

### 5.3 知了精灵状态机

```
idle ──(用户操作/定时)──→ fly ──(到达目标)──→ prune | water | sweep
  ↑                                              │
  └──────────────────────────────────────────────┘
```

精灵行为**由数据驱动**：`cicada: { action, targetTreeId, line }`。前端只做插值与播放，不做决策。

### 5.5 农夫日记页结构（画像锚 + 日记流）

```
<DiaryPage>
├── <ProfileAnchor>            ← 置顶锚点，视觉最强，几乎不变
│   ├── soulType + emoji        ← "深潜型探索者 🧭"
│   ├── description
│   └── <TraitCard> × 3-5       ← 每条含 score 与 evidence
│       └── evidence 链到下方对应日记条目
└── <DiaryStream>               ← 每日刷新
    └── <DiaryEntry> × N        ← eventType: newTree|surge|decay|revive
```

**为什么画像当锚而不是当条目**：日记是**高频**流水（每天可能有一条），画像是**低频**身份信息（几乎不变）。把"你是谁"混进每日流水，会被 `decay`/`surge` 这类事件淹没，用户翻三屏才看到自己的画像，冲击力全失。

**两个接口，一页渲染**：`/api/profile`（画像）+ `/api/diary`（日记流）。接口不合并——分别由不同人开发，互不阻塞。画像更新时在锚点卡上打「已更新」角标。

### 5.6 按天回放（演示杀手锏）

```ts
async function replay(userId: string, days: number[]) {
  let acc: ContentItem[] = [];
  for (const d of days) {
    const slice = await loadDay(userId, d);
    acc = [...acc, ...slice.contents];     // 不可变累加
    await rebuildForest(acc);               // 按需重算
    await sleep(600);                        // 让观众看清生长
  }
}
```

30 秒演示"从荒漠到森林"，比静态展示一棵长好的树震撼得多。

## 7. 关键算法

### 7.1 树 ID 稳定（★ 最重要）

**问题**：全量重聚类会让今天的"AI"树和明天的"AI"树变成两个簇，森林每天洗牌，"生长"的错觉崩塌。

**方案**：增量归类

```ts
async function assign(newContents: ContentItem[], forest: ForestState) {
  const { assignments } = await ai.classify({
    existingTrees: forest.trees.map(t => ({ treeId: t.treeId, name: t.name, category: t.category })),
    newContents,
  });
  // 校验：除非 isNewTree，否则 treeId 必须已存在
  for (const a of assignments) {
    if (!a.isNewTree && !forest.trees.some(t => t.treeId === a.treeId)) {
      throw new Error(`AI 返回了不存在的 treeId: ${a.treeId}`);
    }
  }
  return assignments;
}
```

**校验比信任更重要**——AI 幻觉出的 `treeId` 必须被拦截。

### 7.2 森林布局

**方案**：黄金角圆盘撒点（deterministic，无随机性）

```ts
const GOLDEN = 2.399963;   // 黄金角
trees.map((t, i) => {
  const r = 0.16 + 0.30 * Math.sqrt(i / Math.max(1, trees.length - 1));
  return {
    treeId: t.treeId,
    x: 0.5 + r * Math.cos(i * GOLDEN),
    y: 0.5 + r * Math.sin(i * GOLDEN),
    scale: 0.7 + 0.6 * Math.min(1, t.totalContentCount / 15),
  };
});
```

**为什么不用力导向**：力导向每次结果不同，树木会跳动，破坏"稳定生长"的感知。

### 7.3 叶子状态与生长

```ts
// 快照日与叶子最后活跃日的间隔决定状态
const gap = snapshotDay - lastActiveDay;
const state = gap >= 6 ? "withered" : gap >= 3 ? "fading" : "fresh";

// 树阶段由叶子数决定
const stage = n >= 11 ? "flourishing" : n >= 6 ? "mature" : n >= 3 ? "young" : "sprout";
```

### 7.4 高质量筛选（光合作用报告）

```ts
// 用 voteUpCount 但避免固定阈值（数据跨度从个位数到上千）
const score = (c: ContentItem) => Math.log1p(c.voteUpCount) * (c.source === "favorite" ? 1.5 : 1);
const top = contents.sort((a, b) => score(b) - score(a)).slice(0, 5);
```

对数压缩 + 收藏权重，避免高赞内容完全霸榜。

## 11. 开发顺序建议

**先数据后界面**——这是 48h 最容易犯的错。

```
1. 跑通 ingest → classify → forest.json    （没有 UI 也要先有数据）
2. 用 mock-data 的 expected-forest 直接渲染森林  （先有画面）
3. 接上真实 AI，替换假数据
4. 加动画与精灵
5. 加报告/日记/画像
6. 打磨视觉
```

第 2 步很关键：**先用预生成数据把界面跑起来**，前端不被 AI 阻塞，两边并行。
