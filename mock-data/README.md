# 知了森林 · Mock 数据集说明

> 本文件连同《知了森林 · 接口契约》一起喂给你自己的 AI。
> 契约定义**字段格式**，本文件说明**数据内容与用法**。两者都要。

---

## 一、这是什么

**真实知乎内容 + 我们编排的时间线。**

- **内容是真的**：标题、摘要、链接都来自知乎真实作者的创作，通过知乎官方 CLI 检索获得
- **时间线是编排的**：`interactedAt` 时间戳、主题归属、`source` 字段由我们设定
- **不是**真实用户的真实浏览历史

## 二、归属声明（必须遵守）

| 要求 | 说明 |
|------|------|
| 保留署名与链接 | 展示任何内容时，一并展示 `url` 字段的真实链接 |
| 不冒认创作 | 不得声称这些内容由本应用或当前用户创作 |
| 不宣称真实性 | 答辩/文档中如实说明"数据来源为知乎公开内容，时间线为演示编排" |

这一条既是合规要求，也是加分项：**数据可溯源，比编造标题可信**。

## 四、数据规模

| 用户 | 昵称 | 树 | 叶 | 内容 | 归入主题 | 孤立 |
|------|------|-----|-----|------|---------|------|
| `user-a` | 海沟观测员 | 5 | 8 | 66 | 60 | 6 |
| `user-b` | 半路改道的旅人 | 5 | 7 | 59 | 53 | 6 |
| `user-c` | 什么都想知道的松鼠 | 10 | 10 | 66 | 60 | 6 |

时间跨度：**2026-08-15 → 2026-09-13**（**30 天**，`day-01` 对应 08-15）

30 天跨度是为了让农夫日记能讲**月级**叙事（"这个月你变了"），而不只是"这周"。

`source` 分布约为 搜索 20% / 点赞 35% / 收藏 45%，并按"搜索发现 → 点赞 → 收藏"的行为递进分配：每个叶子里最早的一条是 `search`，最晚的一条是 `favorite`。

每条内容还带 `voteUpCount`（知乎赞同数，0 表示无数据）——**「光合作用报告」筛选"高质量输入"就用这个字段**。真实数据里赞同数跨度很大（个位数到上千），排序时注意别用固定阈值。

## 六、孤立条目（噪声）

每个用户有 **6 条 `category: null` 的条目**（洗衣机选购、路由器信号、科目二技巧这类生活杂事）。它们：

- **存在于** `contents` 数组中
- **不存在于** 任何 `leaves[].contentIds` 中
- 用来演示契约里的"未归类"分支，也让数据更像真实用户

**你的 AI 层要处理它们**：增量归类时接不住就保持未聚类，不要在森林里硬塞一棵树。

## 七、三个用户的剧情线

**做演示和自测时按这个预期走，别把它们当随机数据。**（第 N 天 = 08-15 + N-1）

### user-a 深潜型（海沟观测员）· 默认演示账号

| 时间 | 事件 |
|------|------|
| 第 1 天起 | 人工智能缓慢积累 |
| 第 1–13 天 | 健身活跃 |
| **第 13 天后** | **健身彻底停止 → 枯萎** |
| **第 14 天** | **心理学首次出现 → 新树** |
| 第 14 天 | 「大模型落地」长成人工智能的新叶（老树发新枝） |
| **第 22 天** | **人工智能单日 4 条 → 猛增** |
| 第 21 天后 | 创业与产品停止 |

### user-b 漫游者（半路改道的旅人）

| 时间 | 事件 |
|------|------|
| 第 1 天起 | 历史、文学双主干稳定生长 |
| **第 12 → 16 天** | **艺术空窗 4 天（枯萎），第 16 天恢复 → 复苏素材** |
| **第 16 天** | **哲学首次出现 → 新树** |
| **第 19 天** | **哲学单日 3 条 → 猛增** |
| 第 17 天后 | 社会观察停止 → 枯萎 |

### user-c 杂食（什么都想知道的松鼠）

| 时间 | 事件 |
|------|------|
| 第 6 天 | 摄影单日 3 条 → 猛增 |
| 第 6 天后 | 家居停止 → 枯萎 |
| **第 12 天** | **编程入门首次出现 → 新树** |
| 全程 | 10 棵树各 6 条，**没有主干** |

## 八、可演示的四个场景

**三个用户都能独立触发全部四类事件**，演示时切哪个都不虚：

| 场景 | user-a | user-b | user-c |
|------|--------|--------|--------|
| `newTree` 新树 | 心理学 @第14天 | 哲学 @第16天 | 编程入门 @第12天 |
| `surge` 猛增 | 人工智能 @第22天（单日 4 条） | 哲学 @第19天（单日 3 条） | 摄影 @第6天（单日 3 条） |
| `decay` 枯萎 | 健身止于第13天、创业产品止于第21天 | 社会观察止于第17天 | 家居止于第6天 |
| `revive` 复苏素材 | 2 处空窗后恢复 | 艺术 第12→16天 空窗后恢复 | 8 处空窗后恢复 |

**演示 `revive` 的脚本**（以 user-b「艺术」为例）：

1. 时间轴走到第 15 天 → 农夫日记提示"艺术树在枯萎，要浇水吗"
2. 用户点击浇水 → 写入 `FeedbackSignal(action: "water")`
3. 第 16 天艺术树恢复新叶 → 触发 `revive` 事件

`revive` 是**运行时事件**，靠"浇水动作 + 后续恢复"共同产生，不能只从数据里读出来。

| 附加场景 | 说明 |
|---------|------|
| **画像差异** | 三个用户的树/叶结构截然不同 → 三种不同的 `soulType` |
| **未归类条目** | 每用户 6 条 `category: null` 的孤立内容 |
| **月级叙事** | 30 天跨度支持"这个月你变了"级别的对比 |

## 九、代码里怎么用

### 读全量数据集

```ts
import userA from "@/mock-data/mock/user-a.json";

// userA.contents 即契约 §6 的 ContentItem[]
const aiDocs = userA.contents.filter(c => c.category === "tech");
```

### 演示"森林生长"（推荐）

按天回放，让评委看到森林长出来，而不是直接给一棵长好的树：

```ts
const days = Array.from({ length: 30 }, (_, i) => i + 1);   // 第 1~30 天
const timeline = days.map(d =>
  import(`@/mock-data/mock/days/user-a/day-${String(d).padStart(2, "0")}.json`)
);

// 逐日累加，喂给 AI 归类 → 渲染森林
let accumulated: ContentItem[] = [];
for (const slice of timeline) {
  accumulated = [...accumulated, ...slice.contents];   // 不可变累加
  await rebuildForest(accumulated);                     // 后端按需重算森林
}
```

### 演示兜底（AI 失败时）

```ts
// 现场网络或模型调用出问题时，直接读预生成结果
import fallbackForest from "@/mock-data/expected-forest/user-a.json";
```

## 十、重新生成

改了 `build-dataset.js` 里的 `PLAN`（剧情线）后：

```bash
RAW=./mock-data/raw OUT=./mock-data node ./mock-data/build-dataset.js
```

`PLAN` 里每个叶子有一个 `days` 数组，表示该叶子的内容分别落在第几天。
`dayOf(n)` 把 n 映射为 `2026-09-01 + (n-1) 天`。

```
本项目的演示数据在 mock-data/ 下，格式遵循《知了森林 · 接口契约》。

使用规则：
1. 不要修改 mock-data/raw/ 下的文件，那是原始抓取结果。
2. 读取数据时按契约 §6 的 ContentItem 字段处理；category 为 null 的
   条目是"未归类"的孤立内容，不要强行归类，也不要报错。

5. 需要森林状态时，优先读 expected-forest/（演示兜底）；需要展示
   生长过程时，读 mock/days/ 按天累加。
6. 时间字段是带 +08:00 的 ISO 8601，比较时间请按字符串比较或转成
   同一时区后再比较。
```
